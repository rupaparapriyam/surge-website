Critical Issues (Accessibility & Structural Gaps)

Critical

Missing prefers-reduced-motion Coverage

style.css

The Problem

Currently, the codebase contains zero media queries for prefers-reduced-motion. Users with vestibular conditions or motion sensitivities who have reduced motion enabled in their OS will still experience the dynamic, high-frequency WebGL background ripples, the scrolling 360° bottle rotations, and the 3D card tilt physics. This violates basic accessibility standards.

The Recommendation

Implement an global accessibility override block in style.css to disable transitions, transforms, WebGL background redraws, and scrolling triggers when reduced motion is preferred.

+ @media (prefers-reduced-motion: reduce) {
+   * {
+     animation-delay: 0s !important;
+     animation-duration: 0s !important;
+     animation-iteration-count: 1 !important;
+     transition-duration: 0s !important;
+     scroll-behavior: auto !important;
+   }
+   #bg-canvas, #bottle-canvas {
+     display: none !important; /* Hide dynamic GPU canvases */
+   }
+   .scrambled-card {
+     transform: none !important; /* Flatten 3D card stack */
+   }
+ }

Through Emil's Lens: Accessibility is not optional. When users request no motion, the UI must immediately flatten and become static. Instant state snaps are preferred over any transition for vestibular safety.

Jarring Instant Snap on Product Notification Modal

app.js • line 680

The Problem

The product notification modal (#notify-modal) appears and disappears instantly using inline JS modifications: modal.style.display = "flex" and modal.style.display = "none". This instant snapping feels broken, causing visual disorientation instead of a smooth entrance.

The Recommendation

Refactor modal open/close actions in app.js to toggle an .active class, and style the entrance in CSS using a combination of opacity, scale, and backdrop blurs to materialize the element.

- function openNotifyModal(productName) {
-   modal.style.display = "flex";
- }
+ function openNotifyModal(productName) {
+   modal.classList.add("active");
+ }

Through Jakub's Lens: Elements entering focus should emerge smoothly. We combine opacity + translateY + blur to make the modal card feel material, fading the background backdrop overlay in parallel.

Important Issues (State Polish & Timing)

Important

Jarring State Snap on VIP Success Registration

app.js • line 465

The Problem

On submitting the waitlist form, the email input form is hidden instantly with display: none, and the checkmark success block (#vip-success-msg) pops in instantly with display: block. This lacks timing continuity.

The Recommendation

Transition between form states: smoothly fade out the form elements first, then trigger a scale-up spring animation on the success checkmark to celebrate the registration action.

+ // Fade form out, then scale success checkmark in
+ anime({
+   targets: '#vip-form',
+   opacity: 0,
+   duration: 300,
+   complete: () => {
+     form.style.display = "none";
+     successCard.style.display = "block";
+     anime({
+       targets: successCard,
+       scale: [0.8, 1],
+       opacity: [0, 1],
+       easing: 'easeOutElastic(1, 0.7)'
+     });
+   }
+ });

Through Jhey's Lens: Celebratory moments like waitlist signup should be delightful. A springy scale bounce on the checkmark icon communicates completion with playfulness.

Important

Instant Question Snapping in Grooming Quiz Steps

app.js • line 590

The Problem

When selecting answers in the grooming quiz modal, the active step is changed instantly by toggling .quiz-step.active. Because steps use absolute display: block/none rules, the transition is instant. This breaks visual continuity.

The Recommendation

Implement a slide-fade transition to move questions out to the left while sliding the new question in from the right, maintaining directional flow.

Through Jakub's Lens: Horizontal sliding animations represent progress. Moving from right to left maps to the logical 'Next Step' flow, keeping the user oriented within the quiz steps.

Chronicles Card Desk Fan-Out Entrance

When the "SURGE Chronicles" chapter cards scroll into viewport, they currently load static in their rotated desk positions. Trigger a staggered fan-out animation using ScrollTrigger where cards slide into their scrambled rotation and position offsets one by one, mimicking cards being dealt onto a desk.
